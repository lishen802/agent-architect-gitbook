# 第 16 章 数据问数与分析

> **已有经验**：数据建模、指标口径、SQL 与权限。
>
> **新增问题**：自然语言与业务指标的对应需验证。
>
> **本章产出**：受控问数链路与结果验收口径。

> 本章为按统一模板整理的写作提纲，需在两篇样章试读后扩写；以下是计划讨论的设计问题，不是已完成的实现或实验结论。

## 16.1 需求特征

区分查找既有指标、临时聚合、探索异常与形成经营建议。明确时间、粒度、口径、数据权限和实时性；先比较指标平台与参数化报表。

## 16.2 候选架构与选择依据

优先评估自然语言理解加受控语义查询或参数化接口；不得把生成 SQL 直接等同于获准执行。探索路径确实取决于中间数据时，再比较受限分析循环与固定工作流。需求从查数变为解释原因时，增加证据与假设管理，而不是让相关性自动成为因果结论。

## 16.3 难点

重点分析指标定义、联表关系、时间口径、空值、权限过滤、查询代价与结果解释。将精确运算交给经过校验的计算组件，保留数据与查询版本。

## 16.4 常见坑

讨论只读账户仍可能暴露数据或运行昂贵查询、用语法合法替代业务口径校验，以及把图表趋势写成已确认原因。

## 16.5 评测验收

按固定数据快照检查指标口径、计算结果、权限与资源上限；另评解释是否超出数据支持范围。允许多种等价查询，不强制唯一 SQL 文本。

## 16.6 安全合规

逐项说明字段与行级权限、必要数据范围、外部模型接收的内容，以及明细、导出、轨迹与缓存的保留。涉及个人数据或自动化判断时按附录 D 核对适用要求；基础身份治理回查第 21 章。

## 迁移练习

销售经理问“上个月表现最差的区域是什么”，系统能直接生成 SQL 并排名吗？先按第 2 章的一页方案组织答案，再阅读参考思路。

### 参考思路

**当前选择**：先确认“表现”是收入、利润还是达成率，以及时间和区域口径；使用授权指标接口或经过限制的查询，再解释结果。

**需要追问**：可见区域、退款口径、币种和更新延迟是什么，排序结果是否用于具体人员评价？

**暂不采用的方案**：不把语法合法当作口径正确，不从排名直接生成原因；已有报表足够时不增加 Agent。

**改变选择的条件**：若要求调查下降原因，可以引入多源证据分析，但保留假设与因果结论的区别。
