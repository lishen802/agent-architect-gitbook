# 标准一页方案模板

用途：从需求推导候选方案，不作为已经完成的验收报告。每一项写结论、依据与未决事项；标为“待验证”的项目必须附上对应的实验。

十二项的定义与告警助手示例见[第 2 章 2.4 节](../../part-1/02-architecture-matrix.md)，完整示范见[第一篇小结](../../part-1/reference-architecture.md)。全书的场景章和章末练习都采用这套编号。

## 第一组：问题

| 编号与项目 | 结论、依据与未决事项 |
| --- | --- |
| 1 任务与交付物：使用者、触发时点、输入与交付物 | 待填写 |
| 2 错误后果与边界：错误分级，不可越过的边界 | 待填写 |

## 第二组：方案

| 编号与项目 | 结论、依据与未决事项 |
| --- | --- |
| 3 无需模型的基线 | 待填写 |
| 4 模型职责，以及模型不承担的职责 | 待填写 |
| 5 控制方式、选用模式及未选方案的理由 | 待填写 |

## 第三组：边界

| 编号与项目 | 结论、依据与未决事项 |
| --- | --- |
| 6 信息获取：来源、权限与时效；是否检索 | 待填写 |
| 7 数据处理：敏感性、处理位置、第三方传输与留存 | 待填写 |
| 8 动作与授权：读写性质、授权与审批条件 | 待填写 |
| 9 状态与失败：任务状态、取消、失败与结果不明处理 | 待填写 |

## 第四组：验证

| 编号与项目 | 结论、依据与未决事项 |
| --- | --- |
| 10 评测验收：样例、判定标准与人工责任 | 待填写 |
| 11 成本与延迟：估算假设、并发与预算 | 待填写 |
| 12 最小实验与改变条件：放弃条件，会改变架构的需求变化 | 待填写 |

先写自己的方案，再对照场景篇。表格中的每一格都应写出针对本需求的判断，组件名称本身不是答案。
