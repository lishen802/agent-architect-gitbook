# 前言

大模型正在改变软件能够处理的问题。过去需要人工阅读的文档、解释的告警和整理的业务材料，如今可以成为程序的输入；一些难以穷举规则的任务，也开始能够借助模型完成。但从一次看起来不错的回答，到一个可以交付的软件系统，中间仍然需要明确的设计、验证与运行机制。

《AI 应用开发：从编程思维到系统架构》写给希望进入这一领域的开发者。你可能已经熟悉接口、数据库、测试和服务部署，却还不确定：模型应该放在系统的什么位置？什么时候需要检索，什么时候需要智能体？输出不稳定的组件，如何参与可靠的业务流程？本书围绕这些问题展开。

## 本书写给谁

本书面向具有基本编程和应用开发经验的读者，包括后端、前端、全栈开发者，以及需要设计和交付 AI 应用的技术负责人。阅读前，你应当了解 API 调用、数据结构、异常处理和基本测试方法；进入状态管理与生产治理部分时，数据库、并发和服务运维经验会有所帮助。

本书不要求读者先掌握模型训练算法。重点是如何使用模型构建应用，以及如何对应用的行为负责。核心示例计划以 Go 展示工程实现，设计方法可迁移到其他语言与技术栈。

## 本书希望帮助你建立什么能力

第一种能力是判断问题。面对一项需求，能够识别哪些部分适合规则程序，哪些需要模型理解与生成，哪些值得引入动态决策；同时把“效果不错”转化为可验证的业务标准。

第二种能力是构建应用。从模型接入、提示设计和结构化输出开始，逐步加入工具调用、上下文管理与知识检索，让模型的输入有依据、输出可处理、失败有去处。

第三种能力是设计系统。当应用需要多步执行、修改外部状态或长期运行时，能够处理权限、状态、恢复、人工审批、质量评测与运行成本，使其具备交付和持续改进的条件。

这些能力构成全书的主线：**从业务问题出发，以最小应用验证价值，再根据实际需要演进架构。**

## 为什么从应用走向智能体

有些任务通过一次模型调用就能完成，有些适合预先定义的工作流，还有一些需要根据观察结果不断选择下一步动作。智能体适用于第三类情形，因此本书会先建立应用基础，再深入智能体系统。

当模型参与动作选择时，软件工程需要明确区分建议与执行：

> 模型提议，系统校验，策略裁决，工具执行。

这一原则贯穿工具接入、任务运行、安全设计和生产治理。模型能够提出更丰富的选择，系统仍然需要决定哪些选择可以执行，以及如何判断执行结果。

## 贯穿全书的案例

本书以一个运维助手作为贯穿案例。它从整理告警与生成摘要开始，逐步接入指标、日志、发布记录和运维知识；在此基础上，再引入动态调查、任务恢复与人工审批。

选择这一案例，是因为它集中体现了证据质量、工具调用、执行风险和结果验证之间的关系。相关方法也可用于客服辅助、企业知识问答、业务分析和内部流程自动化。案例采用教学场景与演练数据；任何涉及外部状态变更的能力，都需要明确权限、审批和验收条件。

## 如何阅读本书

全书分为五篇。第一篇建立工程思维，第二篇构建可验证的应用，第三篇设计可控的智能体，第四篇讨论生产运行与治理，第五篇将这些方法汇集到综合案例中。框架相关内容放在附录，供读者将通用原则映射到具体工具。

第一次阅读，建议按篇章顺序推进。已有 AI 应用经验的读者，可以先阅读架构选择与设计原则，再根据当前问题查阅检索、状态、安全或治理章节。详细路径见[导读：本书的学习路径](intro/determinism-vs-probabilistic.md)。
