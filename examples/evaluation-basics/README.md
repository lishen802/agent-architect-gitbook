# 第 6 章：评测记录与汇总示范

本目录演示如何保存任务、候选结果、逐项判定及汇总。所有内容都是教学构造；语义判定是随书编写的参考答案，不是实际模型评分或外部读者评审。程序不调用模型、不联网、不读取生产数据。

## 文件与职责

| 文件 | 内容 |
| --- | --- |
| [cases.json](cases.json) | 六条任务的材料、验收要求、允许变体及预期状态 |
| [runs.json](runs.json) | 每题一次构造结果、结束状态及四项语义参考判定 |
| [summarize.py](summarize.py) | 本地报告契约检查、记录完整性检查与汇总 |
| [summary.json](summary.json) | 本轮实际运行汇总程序得到的输出 |
| [test_summarize.py](test_summarize.py) | 分母、待定、引用错误和缺失判定的关键行为测试 |

示例使用 Python 3.9 或更高版本的标准库，无第三方依赖。从仓库根目录执行：

```sh
python3 -B -m unittest discover -s examples/evaluation-basics -v
python3 -B examples/evaluation-basics/summarize.py
```

预期计数为：计划 6、完成生成 5、契约通过 5、任务通过 2、任务失败 4、待定 0。通过项为 T02、T05。任务集刻意包含错误输出，其中几题共享材料；数字不能当作真实模型质量统计。

## 判定与运行规则

四项语义判定为数值与事件转述、适用范围、不确定性、任务帮助。每项填 `pass`、`fail` 或 `pending` 及理由。整份语义判定可以为 `null`，表示尚未评审；部分字段意外缺失则报记录错误。

程序要求每个任务恰好一条记录。调用超时和错误计入计划任务并记为任务失败，报告契约为不适用。完成生成后，报告契约、预期状态和语义判定共同决定结果；任何已知失败阻断通过。尚无失败但评审不齐时记为待定，不计入通过。

退出码零表示记录汇总完成，不表示所有任务通过。记录损坏导致异常时以非零状态退出。本示例不提供发布自动放行规则。

程序只检查明确列出的字段、枚举、非空文字及引用存在性，不判断自然语言意义，不是完整 JSON Schema 校验器，也不替代第 5 章 Go 应用的校验。语义结果来自记录中的参考判定；故意填错判定，程序不能自动识别。

## 复核与修改

可以复制记录，将一个通过项的 `review` 改为 `null`，观察它变成待定而不是通过；将引用改为 `E999`，观察即使语义判定全通过，任务仍然失败。仅修改候选文字不会让程序自动重判语义，必须重新评审并记录理由。

重复模型试验需要扩展计划次数、试验 ID 与汇总口径，本程序只支持每题一次。接入在线模型还需要真实适配器、版本与用量记录、评审流程和新的验收材料，不能将教学记录的 `origin` 改名后当作实测。

方法与逐题解释见[第 6 章](../../part-2/06-evaluation-basics.md)。
