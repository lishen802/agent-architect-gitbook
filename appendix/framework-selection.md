# 附录 B 框架选型对照

先用第 2 章写明任务与边界，再选择需要框架承担的职责。本附录当前提供比较方法，不给未经版本核验的框架打分，也不根据框架名称推断可靠性保证。

| 比较维度 | 需要向候选实现确认的问题 | 最小验证方式 |
| --- | --- | --- |
| 控制流程 | 固定编排与动态决策怎样表达？ | 复现同一条任务路径与终止条件 |
| 状态 | 谁拥有事实源，怎样持久化和迁移？ | 并发推进、版本冲突与恢复演练 |
| 工具 | 参数、身份、超时和错误如何传递？ | 非法参数、越权与结果不明样例 |
| 人工协作 | 审批与具体动作怎样绑定？ | 拒绝、过期、参数变化与重复回调 |
| 副作用 | 重试和恢复是否会重新执行外部动作？ | 在提交前后注入故障并核对结果 |
| 评测与追踪 | 能否保存必要版本与结果证据？ | 同任务回放、失败归因与脱敏检查 |
| 依赖与退出 | 升级、部署和迁移成本如何？ | 固定版本安装与移除框架后的边界分析 |

候选资料按具体版本维护：

| 阅读入口 | 当前状态 | 可据此得出的结论 |
| --- | --- | --- |
| [LangGraph](langgraph.md) | 阅读提纲，尚未固定和验证实现版本 | 仅表示后续准备考察，不构成选型推荐 |
| [OpenAI Agents SDK](openai-agents-sdk.md) | 阅读提纲，尚未固定和验证实现版本 | 同上 |
| [Google ADK](google-adk.md) | 阅读提纲，尚未固定和验证实现版本 | 同上 |

完成具体适配时，必须记录 SDK 与运行环境版本、官方资料日期、通过的实验与未覆盖范围。正文使用框架无关的契约和状态示意；供应商请求代码与框架配置放入配套目录，避免在方法卷中混入难以维护的 API 操作手册。
