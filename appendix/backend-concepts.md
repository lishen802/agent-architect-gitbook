# 附录 A 后端概念对照表

本表用于迁移经验，不表示右侧能力替代左侧机制。正文中的 AI 应用仍然需要普通软件测试、事务、权限与运维。读表时同时看“可以沿用什么”和“类比在哪里停止”。

| 已有经验 | 可以沿用的部分 | 需要新增或调整的能力 | 类比的边界与阅读入口 |
| --- | --- | --- | --- |
| API 契约与 DTO | 字段、类型、错误语义、版本管理 | 结构化输出、拒绝与截断处理、生成内容校验 | JSON 合法不代表事实正确；第 4、5 章 |
| 单元测试与集成测试 | 业务规则、失败路径、接口和状态验证 | 任务集、内容评审、多次试验与错误分类 | 评测集不替代代码测试；第 6 章 |
| 数据库事务 | 局部原子性、一致性约束、并发更新 | 外部副作用核对、长流程补偿、审批绑定 | 审批不提供原子性，补偿不保证抹去全部后果；第 11、12 章 |
| HTTP 超时与重试 | 截止时间、退避、取消传播 | 生成重复费用、工具结果不明与任务预算 | 超时不表示外部动作没有发生；第 7、12 章 |
| 幂等与业务操作号 | 识别同一操作的重试 | 将模型候选动作映射为稳定、受控的执行请求 | 参数相同不一定是同一业务意图；第 7、15 章 |
| 状态机与事件记录 | 显式状态转换、版本、重放与审计 | 模型提出下一步，应用裁决并推进状态 | 普通自然语言历史未定义事务与恢复规则；第 11 章 |
| 缓存 | 有效期、键设计、权限隔离与失效 | 区分回答缓存、推理计算缓存与上下文选择 | 上下文管理不是缓存的改名；第 8、22 章 |
| 搜索系统 | 文档处理、索引、过滤、更新与排序 | 让生成结论可追溯到适用证据 | 检索到材料不等于材料支持结论；第 9、14 章 |
| RBAC / ABAC 与服务身份 | 主体、资源、权限与审计 | 为模型候选动作建立独立授权边界 | 角色提示词不能替代权限系统；第 7、21 章 |
| 定时任务与工作流 | 调度、依赖、等待、恢复 | 识别确实需要动态决策的局部步骤 | 工作流不等于 DAG，调用模型不必成为 Agent；第 2、10 章 |
| 分布式服务拆分 | 职责、协议、共享状态与故障隔离 | 判断是否需要多个模型角色与独立上下文 | 多智能体不等于微服务，同意同一答案不等于独立证据；第 13 章 |
| 日志、指标与追踪 | 请求关联、耗时、错误与故障定位 | 关联任务结果、提示与知识版本、评价反馈 | 调用全部成功不代表任务正确；第 20 章 |
| 容量规划与成本核算 | 预算、队列、配额、瓶颈分析 | 生成长度、动态步数、评测与人工复核成本 | 单 Token 价格不代表成功任务总成本；第 22 章 |
| 数据治理 | 分类分级、最小必要、保留与删除 | 输入、检索、模型服务、记忆与轨迹中的数据流 | 使用已有模型不自动免除应用侧责任；附录 D、第 21 章 |
| 人机交互与审批 | 用户意图确认、审阅与操作留痕 | 区分草稿、信息不足、待审批和结果待核对 | 点过同意不代表后续修改的动作也被批准；第 12、14、15 章 |

例如，设计一个报销助手时，可以从熟悉的订单状态机和权限模型开始，再补充单据抽取、缺失字段处理和任务评测。模型可以帮助识别票据信息；金额运算、审批权限和支付提交仍由相应业务机制承担。是否增加检索或智能体循环，需由实际信息来源与行动路径决定。
