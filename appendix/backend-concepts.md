# 附录 A 后端概念对照表

本附录用于迁移经验。右栏列出的新能力是对左栏机制的补充，正文中的 AI 应用仍然需要普通软件测试、事务、权限与运维。每张表后列出类比在哪里停止，以及阅读入口。

## A.1 接口与测试

| 已有经验 | 可以沿用的部分 | 需要新增或调整的能力 |
| --- | --- | --- |
| API 契约与 DTO | 字段、类型、错误语义、版本管理 | 结构化输出、拒绝与截断处理、生成内容校验 |
| 单元测试与集成测试 | 业务规则、失败路径、接口和状态验证 | 任务集、内容评审、多次试验与错误分类 |

- API 契约：JSON 合法只说明格式正确，事实是否正确另需检查（第 4、5 章）。
- 测试：评测集与代码测试各管一层，相互补充（第 6 章）。

## A.2 状态与可靠性

| 已有经验 | 可以沿用的部分 | 需要新增或调整的能力 |
| --- | --- | --- |
| 数据库事务 | 局部原子性、一致性约束、并发更新 | 外部副作用核对、长流程补偿、审批绑定 |
| HTTP 超时与重试 | 截止时间、退避、取消传播 | 生成的重复费用、工具结果不明与任务预算 |
| 幂等与业务操作号 | 识别同一操作的重试 | 将模型候选动作映射为稳定、受控的执行请求 |
| 状态机与事件记录 | 显式状态转换、版本、重放与审计 | 模型提出下一步，应用裁决并推进状态 |
| 缓存 | 有效期、键设计、权限隔离与失效 | 区分回答缓存、推理计算缓存与上下文选择 |

- 事务：审批提供的是业务确认，原子性仍由事务保证；补偿也未必能抹去全部后果（第 11、12 章）。
- 超时：超时之后，外部动作可能已经发生（第 3 章 3.6 节，第 7、12 章）。
- 幂等：参数相同的两次请求，可能是两个独立的业务意图（第 7、15 章）。
- 状态机：普通自然语言历史没有定义事务与恢复规则（第 3 章 3.4 节，第 11 章）。
- 缓存：上下文管理决定本次调用看到什么，与缓存的复用目的不同（第 3 章 3.3 节，第 8、22 章）。

## A.3 知识、权限与数据

| 已有经验 | 可以沿用的部分 | 需要新增或调整的能力 |
| --- | --- | --- |
| 搜索系统 | 文档处理、索引、过滤、更新与排序 | 让生成结论可追溯到适用证据 |
| RBAC / ABAC 与服务身份 | 主体、资源、权限与审计 | 为模型候选动作建立独立授权边界 |
| 数据治理 | 分类分级、最小必要、保留与删除 | 输入、检索、模型服务、记忆与轨迹中的数据流 |
| 人机交互与审批 | 用户意图确认、审阅与操作留痕 | 区分草稿、信息不足、待审批和结果待核对 |

- 搜索：检索到材料之后，还要判断材料是否支持结论（第 9、14 章）。
- 权限：角色提示词代替不了权限系统（第 3 章 3.5 节，第 7、21 章）。
- 数据治理：使用已有模型服务，应用侧的数据处理责任依然存在（附录 D、第 21 章）。
- 审批：批准只覆盖当时看到的动作，之后修改过的动作需要重新判断（第 12、14、15 章）。

## A.4 编排与运行

| 已有经验 | 可以沿用的部分 | 需要新增或调整的能力 |
| --- | --- | --- |
| 定时任务与工作流 | 调度、依赖、等待、恢复 | 识别确实需要动态决策的局部步骤 |
| 分布式服务拆分 | 职责、协议、共享状态与故障隔离 | 判断是否需要多个模型角色与独立上下文 |
| 日志、指标与追踪 | 请求关联、耗时、错误与故障定位 | 关联任务结果、提示与知识版本、评价反馈 |
| 容量规划与成本核算 | 预算、队列、配额、瓶颈分析 | 生成长度、动态步数、评测与人工复核成本 |

- 工作流：DAG 只是工作流的一种形式；调用模型的流程也可以完全由代码控制（第 2、10 章）。
- 服务拆分：多智能体的拆分依据与微服务不同，多个角色给出同一答案也不构成独立证据（第 13 章）。
- 观测：调用全部成功，任务结果仍可能错误（第 20 章）。
- 成本：单 Token 价格反映不了成功任务的总成本（第 2 章 2.7 节，第 22 章）。

例如，设计一个报销助手时，可以从熟悉的订单状态机和权限模型开始，再补充单据抽取、缺失字段处理和任务评测。模型可以帮助识别票据信息；金额运算、审批权限和支付提交仍由相应业务机制承担。是否增加检索或智能体循环，由实际信息来源与行动路径决定（[第一篇小结](../part-1/reference-architecture.md)给出了完整示范）。
