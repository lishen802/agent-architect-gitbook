# 导读：从已有工程经验出发

AI 应用需要新的交互方式，也继续依赖已有的软件工程能力。学习的重点，是理解这些能力在引入模型后如何延伸，以及哪些问题需要新的验证方法。

| 已有经验 | 可以迁移的能力 | 需要补充的认识 |
| --- | --- | --- |
| API 与业务服务开发 | 模型接口封装、工具适配、参数校验与错误处理 | 模型返回格式正确，不代表事实或业务含义正确 |
| 数据库与状态机 | 任务状态、版本控制、持久化与恢复 | 对话记录不能独自承担业务状态管理 |
| 搜索与数据处理 | 文档处理、索引、权限过滤与数据更新 | 检索质量和回答质量需要分别评估 |
| 并发与分布式系统 | 调度、超时、幂等、隔离与资源管理 | 工具超时后需要核对实际结果，不能默认动作未执行 |
| 自动化测试与质量保障 | 回归样例、边界验证与发布检查 | 开放式任务需要任务级评测和必要的人工判断 |
| 前端与交互设计 | 流式展示、任务进度、取消与错误反馈 | 应让用户理解证据、等待状态和需要接管的时机 |
| 服务运维与平台工程 | 监控、限流、容量、配额与故障处置 | 需要同时观察任务质量、响应时间和成功任务成本 |

不必在开始前掌握表中全部能力。先选一个边界清晰的业务任务，完成可验证的最小应用，再随任务复杂度补充状态、检索、权限和治理能力。
