# 一页方案模板

用途：从需求推导候选方案，不作为已经完成的验收报告。填写时区分事实、项目约定与待验证假设。

| 项目 | 结论、依据与未决事项 |
| --- | --- |
| 使用者、触发时点、输入与交付物 | 待填写 |
| 错误后果、不可越过的边界 | 待填写 |
| 无需模型的基线 | 待填写 |
| 模型承担的具体职责 | 待填写 |
| 控制方式及未选方案的理由 | 待填写 |
| 信息来源、权限与时效；是否检索 | 待填写 |
| 数据敏感性、处理位置、第三方传输与留存 | 待填写 |
| 工具动作、授权、审批条件 | 待填写 |
| 任务状态、取消、失败与结果不明处理 | 待填写 |
| 评测样例、判定标准与人工责任 | 待填写 |
| 成本、延迟、并发与预算假设 | 待填写 |
| 最小验证实验与放弃条件 | 待填写 |
| 什么需求变化会改变架构 | 待填写 |

参考方法见[第 2 章](../part-1/02-architecture-matrix.md)。先写自己的方案，再对照场景篇；不要直接用组件名称填满表格。
